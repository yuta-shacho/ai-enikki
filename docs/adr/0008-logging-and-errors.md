# 0008. ログの形式とエラーの分類

- 状態: 承認
- 日付: 2026-10-14

## 背景

- 報酬制度（2-A-2）では、エラーを「正常なエラー」「異常なエラー」「想定外のエラー」に分け、それぞれの扱いを事前に決めておくことが求められる
- ログは、どこで出たか（時刻、ファイル名、行数）がわかり、監視システムで解析できる構造化データにする必要がある
- 本番の Lambda では、標準出力に出したログが自動で CloudWatch Logs に保存される
- 1回の操作が、Next.js と Go の2つをまたぐ

## 選択肢

### ログの形式

#### A. JSON を標準出力に出す

- 良い点: CloudWatch Logs Insights でそのまま検索や集計ができる。ローカルでも `docker compose logs` で同じものが見える
- 悪い点: 人が目で読むには少し見にくい

#### B. 人が読みやすいテキスト

- 悪い点: 監視システムで解析しにくい

### ログのライブラリ

- Go: 標準の `log/slog`。JSON での出力と、ファイル名・行数の付与が標準でできる
- Next.js: `pino`。JSON でログを出す定番で、速く、設定が少ない

## 決定

JSON を標準出力に出す。Go は `log/slog`、Next.js は `pino` を使う。

### 必ず入れる項目

| 項目         | 例                                      |
| ------------ | --------------------------------------- |
| `time`       | `2026-10-13T21:00:00.123+09:00`         |
| `level`      | `INFO`                                  |
| `msg`        | `今日の日記はすでにある`                |
| `source`     | `apps/api/internal/diary/service.go:42` |
| `request_id` | `01J9...`                               |

Next.js はビルドでファイルがまとめられ、ファイル名と行数がそのままでは出ない。そのため `source` の代わりに `module`（どの処理か）を入れ、エラーにはスタックトレースを付ける。

- リクエストの終わりに1行: `method`、`path`、`status`、`duration_ms`
- エラーのとき: `error_kind`、`error_code`、`error`（詳細）。想定外のエラーでは、スタックトレースも付ける

### エラーの分類と扱い

| 分類（`error_kind`）           | 定義                                 | 例                              | ログのレベル                            | 扱い                                 |
| ------------------------------ | ------------------------------------ | ------------------------------- | --------------------------------------- | ------------------------------------ |
| 正常なエラー（`normal`）       | ユーザー起因で、起こるのが正常なもの | 入力の誤り、同じ日の2枚目の提出 | INFO                                    | 4xx を返し、理由をメッセージで伝える |
| 異常なエラー（`abnormal`）     | システム起因で、予期できるもの       | DB につながらない               | 再試行で回復したら WARN、だめなら ERROR | 再試行する。だめなら 5xx を返す      |
| 想定外のエラー（`unexpected`） | 本来は起こらないもの                 | データの不整合、panic           | ERROR                                   | 5xx を返す。通知して人が対応する     |

### request_id

Next.js で作り、`X-Request-Id` ヘッダーで Go に渡す。レスポンスにも付け、画面のエラーからログをたどれるようにする。

### ログに出さないもの

API キー、Cookie、パスワード、JWT、絵の中身、一言の本文

## 結果

### 良くなること

- 1回の操作を、`request_id` で Next.js と Go をまたいで追える
- エラーの分類がログに残るので、想定外のエラーだけを数えて通知できる

### 悪くなること・リスク

- ログの項目を、2つの言語で揃え続ける必要がある

### 後で決めること

- 想定外のエラーの通知（Sentry）と、CloudWatch アラームの条件
