# 0007. 開発ツール

- 状態: 承認
- 日付: 2026-10-14

## 背景

- 誰でもすぐに同じ開発環境を作れるようにしたい（1-B-1）
- TypeScript と Go の2つの言語を、1つのリポジトリで扱う
- 開発者は1人。ツールの数と手間は少なくしたい

## 選択肢と決定

### 言語のバージョン管理: mise

| 候補                                         | 良い点                                                                      | 悪い点                               |
| -------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------ |
| **mise**                                     | Node.js、pnpm、Go、Go の開発用ツールを1ファイルで固定できる。タスクも書ける | 新しく入れる道具が1つ増える          |
| asdf                                         | 実績がある                                                                  | 遅い。タスクの機能がない             |
| 各言語の仕組み（nvm、`go.mod` の toolchain） | 追加の道具が要らない                                                        | 手順が言語ごとにバラバラになる       |
| Dev Container                                | 環境をまるごと揃えられる                                                    | 作るのに時間がかかる。VS Code が前提 |
| Nix（devbox など）                           | OS のライブラリまで揃う                                                     | 覚えることが多い                     |

### パッケージマネージャー: pnpm

| 候補     | 良い点                                                                           | 悪い点                                                      |
| -------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **pnpm** | workspace が安定している。Next.js、CDK、Better Auth の公式の手順がそのまま使える | 特になし                                                    |
| bun      | インストールが速い。TypeScript を直接実行できる                                  | 本番の Lambda は Node.js なので、ローカルと実行環境がずれる |
| npm      | 追加の道具が要らない                                                             | 遅い                                                        |

### TypeScript の lint と整形: Oxlint＋Oxfmt

| 候補              | 良い点                                                                                         | 悪い点                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Oxlint＋Oxfmt** | 速い。Next.js 用のルールがある。Oxfmt は Prettier と互換なので、問題があれば Prettier に戻せる | Oxfmt はまだベータ版。型情報を使うチェックは成熟の途中 |
| Biome             | lint と整形が1つの道具で済む                                                                   | Next.js 用のルールは ESLint より少ない                 |
| ESLint＋Prettier  | ルールが一番揃っている。情報が多い                                                             | 道具と設定が2つずつになる                              |

新しい道具を試したいという学習の目的もあって、Oxlint を選んだ。Oxlint では React と Next.js のルールを有効にする。

### Go の lint と整形: golangci-lint

複数の linter をまとめて動かせる、事実上の標準。標準のセットに errorlint（エラーの比較やラップの書き方を確かめる）を足す。整形は gofmt と goimports で行う。

### タスクの実行: mise のタスク

| 候補                      | 良い点                                           | 悪い点                           |
| ------------------------- | ------------------------------------------------ | -------------------------------- |
| **mise のタスク**         | `mise.toml` にまとめられる。言語をまたいで書ける | mise が前提になる                |
| Makefile                  | どこにでもある                                   | 書き方に癖がある（タブ必須など） |
| Taskfile                  | Go の界隈で人気                                  | 道具が1つ増える                  |
| `package.json` の scripts | TypeScript だけなら自然                          | Go のタスクを書くと不自然になる  |

### コミット前の自動チェック: 入れない

1人の開発で、CI もある。lefthook や husky は入れず、CI で止める。

### 依存パッケージの更新: Dependabot

| 候補           | 良い点                                           | 悪い点                                      |
| -------------- | ------------------------------------------------ | ------------------------------------------- |
| **Dependabot** | GitHub に組み込まれていて、設定ファイル1つで動く | コミットの本文が長く、3行のルールに合わない |
| Renovate       | コミットの本文を設定で変えられる                 | GitHub App の導入と設定の手間がかかる       |

週1回、まとめて1つの PR で更新する。Dependabot のコミットだけ、commitlint の対象から外す。

### Docker の実行環境: OrbStack

開発者の Mac では OrbStack を使う。Docker 互換なので、Docker Desktop など他の実行環境でも同じように動く。

## 結果

### 良くなること

- `mise install` と `pnpm install` の2つで開発環境が揃う
- lint と整形のコマンドは、ローカルでも CI でも `mise run lint` で同じになる

### 悪くなること・リスク

- Oxfmt はベータ版なので、整形の結果が将来変わることがある
- main には、Dependabot の長いコミットメッセージが例外として残る
