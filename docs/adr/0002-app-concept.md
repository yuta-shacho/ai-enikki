# 0002. 作るもの: AI が描く絵日記

- 状態: 承認
- 日付: 2026-10-14

## 背景

- エンジニア報酬制度の評価項目（目標は LV1）を、2026年12月1日までに満たしたい。使える時間は約42時間
- スクラッチ開発の成果物には「Getting Started 程度ではない、アプリ特有のビジネスロジック」が求められる
- 学習と評価のための題材なので、多くの人に使われる必要はない。そのかわり、著作権などの扱いに時間を取られたくない
- AI のエージェントが CLI から Web アプリを操作する使い方が増えている。この流れも題材に入れたい

## 選択肢

### A. PDF 本棚

- 良い点: 自分が欲しいもの
- 悪い点: 公開すると著作権や DRM の扱いが面倒。自分だけで使うなら、ローカルのツールの方が向いている

### B. SNS や日記などの定番アプリ

- 良い点: 練習の題材として定番で、設計の情報が多い
- 悪い点: そのままだと Getting Started 程度に見えやすい。アプリ特有のルールを別に考える必要がある

### C. 開発日報

- 良い点: AI が CLI から書き込む流れを自然に作れる
- 悪い点: Web アプリである必然性が弱い。ファイルやチャットでも済む

### D. AI が描く絵日記

- 良い点: AI が絵を描き、人間が一言とはんこを付けるという役割分担がある。1日1枚、はんこを押すまで非公開など、アプリ特有のルールを作れる。公開ページがあるので、Web アプリである意味がある
- 悪い点: AI が描いた SVG を安全に表示する工夫が要る

## 決定

D の AI が描く絵日記を作る。コンセプトは「AI との開発の思い出」。

- AI（Claude Code など）が、その日の開発を振り返って絵（SVG）を描き、CLI から提出する
- 人間が絵に一言とはんこを付ける。はんこを押すと公開される
- 対象の利用者は、CLI を使える AI と一緒に開発するエンジニア

アプリ特有のルール（詳しくは機能要件で決める）:

1. 1日1枚（日本時間）。同じ日の2枚目は受け付けない
2. AI は提出だけができる。人間がはんこを押すまで非公開
3. 一言は100文字以内で、1件に1つ
4. はんこは3種類（はなまる / よくできました / もうすこし）

## 結果

### 良くなること

- 日付の判定、状態の遷移、AI と人間の権限の違いなど、異常系とテストの題材が多い
- 人間、AI、サーバーのやりとりを、シーケンス図や状態遷移図にできる

### 悪くなること・リスク

- 範囲を広げると時間内に終わらない。次のものは外した
  - 7日たつと確定して編集できなくなるルール（編集できるかどうかは単純に決めればよい）
  - 公開範囲の細かい設定、連続記録
- 対象を開発者に絞るので、使える人は限られる

### 将来の拡張

- 開発以外で AI を使う人も対象にする。CLI を使えない AI のために MCP サーバーなどで提出できるようにし、GitHub を持たない人のために Google ログインを足す
